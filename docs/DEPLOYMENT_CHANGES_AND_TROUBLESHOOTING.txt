1. CI/CD PIPELINE: IMAGE PULL & ROLLING UPDATE FIX
--------------------------------------------------------------------------------
* Location: .github/workflows/ci-cd.yml

* Issue:
  The K3s cluster was not pulling the new images upon deployment. Because the 
  image tag remained ":latest" in the manifests, 'kubectl apply' did not see a 
  change in the Pod template specification. Therefore, Kubernetes treated the 
  apply as a no-op and did not restart the pods to pull the new builds.

* Fix:
  1. Updated the 'push-images' job to tag both backend and frontend images 
     with BOTH 'latest' and the unique Git Commit SHA ('${{ github.sha }}').
  2. Updated the 'deploy-k3s' job to dynamically replace ':latest' with the 
     Git Commit SHA in the manifests before running 'kubectl apply'.

* Code Changes in .github/workflows/ci-cd.yml:
  - Inside `Build and push backend` & `Build and push frontend` steps:
    tags: |
      ravindudilhan/rebuild-backend:latest
      ravindudilhan/rebuild-backend:${{ github.sha }}

  - Added dynamic tag replacement before applying manifests:
    - name: Update image tags in manifests
      run: |
        sed -i "s|ravindudilhan/rebuild-backend:latest|ravindudilhan/rebuild-backend:${{ github.sha }}|g" k8s/backend.yaml
        sed -i "s|ravindudilhan/rebuild-frontend:latest|ravindudilhan/rebuild-frontend:${{ github.sha }}|g" k8s/frontend.yaml

  - Added Grafana ingress application:
    - name: Apply Grafana ingress manifest
      run: kubectl apply -f k8s/grafana-ingress.yaml

2. EMAIL SERVICE SMTP PRODUCTION CONFIGURATION
--------------------------------------------------------------------------------
* Location: k8s/backend.yaml & backend/config/settings.py

* Issue:
  Email sending worked locally but failed entirely when deployed.

* Root Cause:
  Locally, 'EMAIL_BACKEND' was set to the Console Backend (which just outputs 
  emails to the terminal console). In production, 'EMAIL_BACKEND' was not 
  defined in the container environment variables. Thus, it defaulted back to the 
  Console Backend and merely printed the emails to the container stdout logs 
  instead of forwarding them to the SMTP server.

* Fix:
  Added SMTP environment variables to the backend container deployment definition.

* Code Changes in k8s/backend.yaml:
  Added under the backend container spec:
  - name: EMAIL_BACKEND
    value: "django.core.mail.backends.smtp.EmailBackend"
  - name: EMAIL_HOST
    value: "smtp.gmail.com"
  - name: EMAIL_PORT
    value: "587"
  - name: EMAIL_USE_TLS
    value: "True"

7. KUBERNETES SERVICEMONITOR FOR METRICS DISCOVERY
--------------------------------------------------------------------------------
* Location: k8s/django-servicemonitor.yaml & k8s/backend.yaml

* Description:
  Added a Kubernetes 'ServiceMonitor' resource to allow the Prometheus Operator
  (running in the 'monitoring' namespace) to automatically auto-discover and
  scrape the Django backend metrics from the 'rikili001' namespace.

* Fixes & Updates:
  1. ServiceMonitor API Version:
     - Corrected apiVersion from 'v1' to 'monitoring.coreos.com/v1' to match 
       the Prometheus Operator CRD requirement.
  2. Named Service Ports Alignment:
     - Prometheus Operator ServiceMonitors match target ports by name, not
       by numeric values. 
     - Named the backend Service port 'http' in 'k8s/backend.yaml'.
     - Set the ServiceMonitor endpoint target port to 'http'.

* Code Changes in k8s/django-servicemonitor.yaml:
  apiVersion: monitoring.coreos.com/v1
  kind: ServiceMonitor
  metadata:
    name: django-metrics
    namespace: monitoring
  spec:
    selector:
      matchLabels:
        app: backend
    namespaceSelector:
      matchNames:
        - rikili001
    endpoints:
    - port: http
      path: /metrics
      interval: 30s

* Code Changes in k8s/backend.yaml:
  Updated Service ports list to assign the name 'http':
  ports: [{ name: http, port: 8000 }]

* Pipeline Updates (.github/workflows/ci-cd.yml):
  Added a step to apply the ServiceMonitor manifest during deployment:
  - name: Apply ServiceMonitor manifest
    run: kubectl apply -f k8s/django-servicemonitor.yaml
